## Architecture Philosophy

### The Five Pillars

1. **Security by Default** -- Never bolt on security; architect it in
2. **Performance by Measurement** -- Profile before you optimize
3. **Accessibility by Design** -- If it is not accessible, it is not done
4. **Cost by Architecture** -- Choose patterns that scale affordably
5. **Platform by Abstraction** -- Write once, deploy everywhere intelligently

## UI/UX Principles

### The Golden Rules

1. **3-Click Rule** -- Any action reachable in 3 or fewer interactions
2. **Fitts Law** -- Important targets are large and close
3. **Hicks Law** -- Reduce choices to reduce decision time
4. **Millers Law** -- Group information in chunks of 7 plus/minus 2
5. **Doherty Threshold** -- Response time under 400ms feels instant

## Project Checklist

### Pre-Development
- Define project scope and requirements
- Create threat model (STRIDE analysis)
- Select tech stack using cost optimization guide
- Design UI/UX wireframes following cognitive principles
- Set up CI/CD pipeline
- Configure security scanning (SAST + DAST)

### Development
- Implement zero-trust architecture
- Apply input validation on ALL entry points
- Use parameterized queries (no string concatenation)
- Implement rate limiting and circuit breakers
- Add comprehensive logging (no sensitive data in logs)
- Write unit tests (greater than 90 percent coverage)
- Run fuzz testing on all parsers
- Perform dependency audit

### Pre-Deployment
- Penetration testing (OWASP Top 10)
- Performance benchmarking (Lighthouse greater than 95)
- Accessibility audit (WCAG 2.2 AA minimum)
- Legal compliance review (GDPR, CCPA, etc.)
- License compatibility check
- Documentation completeness review

### Post-Deployment
- Monitor error rates and response times
- Set up automated security scanning
- Configure backup and disaster recovery
- Establish incident response plan
- Collect user feedback continuously
- Schedule regular dependency updates
